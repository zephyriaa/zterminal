## Newly reproduced correctness defect

The current viewport conversion assumes all adjacent timestamps are one interval apart. A two-bar native scene at UTC milliseconds 60,000 and 180,000, interval 60,000, should have full semantic bounds 60,000–240,000. Its fractional range 120,000–240,000 must restore and round trip. All three independently expected checks failed in `out/renderer-r1/gap-red.log`.

The source correction interpolates actual adjacent timestamps, uses the final bar completion for the final boundary, and explicitly quantizes only the ChartDocumentV3 viewport to milliseconds. Exact nanoseconds remain in the scene. All three checks pass in `gap-green.log`; the native test executable exits zero. A first build attempt used the existing conversion helper with the wrong signature and failed; the corrected build passed. This fix does not address the product presentation rejection.
