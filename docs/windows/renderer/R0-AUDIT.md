## Verified native capability

`apps/windows-host/src/main.cpp` implements original D3D11 shaders, hardware/WARP selection, HWND and composition flip-sequential swap-chain paths, retained vertices, revisions, resize and attempted device recovery. `native_chart_host.h` exposes one global chart presentation; `MainWindow.xaml.cpp` attaches it to native WinUI `SwapChainPanel`, scales pointer coordinates into physical pixels and handles capture loss. This is native Windows presentation, not WebView.

Current rendering is narrower than its supporting domain:

1. Rust bridge schema **1** and `local_scene::Candle` retain `open_time_ns`, signed integer OHLC ticks and volume. `apply_local_scene_result` immediately casts absolute ticks to double and discards time/volume. `ChartCandle` has only four doubles. Metadata, exact price/quantity scale, dataset hash/revision, ReplayClock, drawings and studies do not reach this render input.
2. Geometry selects at most **2,000** candles; default view is **600**. Price normalization is linear with 8% symmetric padding and a hard minimum range/padding of 1; bodies/wicks use normalized-width minimums. All geometry fills the whole surface; no pane/axis regions or real chart text exist. The full-window viewport is not a semantic layout.
3. Crosshair draws lines, without time/price labels or accessible values. Drag pans within the loaded vector. Wheel zoom multiplies integer visible count by 0.8/1.25 and clamps first; it does not anchor under the pointer. Win32 Home/End/Page keys reload bounded scenes through subprocesses; WinUI does not wire keyboard navigation into the surface. Capture/focus/minimize/DPI/monitor/device recovery are not accepted merely because handlers exist.
4. Rust local scene preparation rejects degraded/gapped/noncontiguous input and decodes up to **100,000 bars per segment**; it integrity-checks/decodes a complete segment before slicing. Visible output is bounded, but repeated paging still spawns a process and rereads/decodes history. This is a baseline, not indexed million-bar interactive performance.
5. `local_scene_bridge.cpp` accepts only positive volume, parses a tightly ordered JSON shape with regex and does not validate every requested/returned bound/timestamp relation itself. Zero volume is a missing chart capability. Preserve upstream fail-closed checks, add explicit schema/bounds/units/revision checks before extending it; do not silently loosen research acceptance.
6. WinUI default launch visibly shows **LOCAL DATA UNAVAILABLE**, named Price chart group, native caption controls and an empty research surface. Workspaces/Datasets/Research/Charts have no attached services/actions; clicking Workspaces did not open a library. Appearance dialog has transient controls only. The UI cannot yet perform workspace → import → save → restart. A journal command smoke is not that journey.
7. The Win32 host is event-driven while idle; the WinUI host calls render on a 16ms timer even for static/unavailable content. D3D creation uses BGRA support, without the debug-layer flag. Device recreation has error handling but no deliberate injection command. Alpha blending and pane clipping/text resources require implementation; composition uses ignored swap-chain alpha, not a tested translucent chart path.

The diagnostic host links Direct2D/DirectWrite but does not use them for chart labels; the composition library links only D3D/DXGI/compiler/PSAPI. Geist-Regular.ttf is present in WinUI; Geist Mono is missing there. Native font assets are not automatically approved merely because they are bundled.

### Geometry contract for R1

- Canonical instants/integers → logical bar/time positions → pane-local **DIP** (Windows) or **CSS px** (web) → physical px using measured DPI/DPR → GPU normalized positions. Layout/pointer use the same immutable transform snapshot/revision. GPU coordinates never contain large epoch timestamps or absolute exact prices.
- With top T, bottom B, positive plot height H=B−T and linear range [p0,p1], y=B−H*(p−p0)/(p1−p0); inverse p=p0+(B−y)*(p1−p0)/H. Inversion swaps direction consistently. Use explicit minimum tick-derived span for equal prices; empty/single/very narrow plots return defined availability/layout results, not NaN or arbitrary 1-price distortion.
- Log mode transforms ln(p) only for p>0; percentage transforms 100*(p/base−1) for a declared nonzero finite stable base. Reject/withhold invalid mode inputs. Margins shrink usable height independently and must leave a positive plot. R1 linear/UTC; R2 other scales/policies.
- Bar-index axis x=L+(logical−firstLogical+0.5)*spacing; use owned `timeToLogical`/`logicalToTime` interpolation through real timestamps for time anchors across gaps. Gap compression is a presentation choice; expected 0,60,180s maps 120s to logical1.5. Future whitespace creates no observations. Cursor zoom derives new firstLogical from the same under-pointer logical coordinate before/after spacing change.
- Geometry tolerance ≤0.25 DIP roundtrip/zoom-anchor, native/web shared semantic golden difference ≤0.5 DIP; exact tick/quantity hits/labels must be exact, with no floating tolerance. DPR conversion is applied once. R1 independently test p100/110/120 at y200/100/0, adjacent ticks beyond 2^53 after local subtraction, one-bar/doji/zero volume, negative linear price, resize/cancel and future extreme invariance.
- Order: background/grid → clipped series/volume → approved overlays/drawings → selected handles → crosshair/axis labels/chrome. Measured text, collision-free ticks and axis regions are separate from plot hits. Use actual font metrics; do not inherit existing estimated text bounds as an accepted standard.

## Architecture decision ADR-R0-01

**Choose existing D3D11/WinUI native host + C++ double layout/geometry over exact Rust data; original TypeScript/Canvas 2D web implementation second, with shared semantic fixture files.** Rust retains verification/storage/replay/research ownership. Extract only currently intermingled transforms/geometry/input needed for R1; keep functioning device/window/swap-chain code. Native DirectWrite/Direct2D evaluation targets text measurement/rendering on the existing BGRA device/backbuffer, per-pane clips, premultiplied drawing alpha where required, deterministic COM lifetimes and device recreation. No new third-party graphics dependency is selected.

Reasons: native C++ renderer already builds/runs; its narrow geometry is cheap to extract/test. Moving all rendering to Rust or adding WASM now adds FFI/toolchain/resource costs without a measured need. Equivalent C++/TS math maintained through independently specified golden inputs/results is the smaller first solution. If future measurements justify sharing pure math in Rust/WASM, document that later decision; do not make R1 wait for it.

Canvas 2D is the R5 default. No measured target workload justifies WebGL yet. Keep ordinary backend-owned commands for actual series/text/clip primitives; no universal graphics abstraction. Share scene meaning and fixture schema, not platform glyph rasterization. Native and browser maintain their own fixed-font/OS/DPI raster goldens. React continues as the web host, never the Windows shell.
